# 02 — The font file format, as actually parsed

A StepMania bitmap font is one `.ini` plus one PNG per page, in the same
directory. This describes the format as `Font::LoadFontPageSettings` really
reads it, including behaviour that is not documented anywhere.

`smfont.py` implements this; it is the reference if anything below is unclear.

---

## Filenames

```
<stem>[ [<page>]] <cols>x<rows>[ (<hints>)].png
```

| part | meaning |
|---|---|
| `<stem>` | must equal the ini filename without `.ini` |
| `[<page>]` | page name; omitted means `main` |
| `<cols>x<rows>` | frames **wide × high** — not pixels |
| `(<hints>)` | comma-separated; `res WxH`, `doubleres`, `dither`, `mipmaps`, `stretch`, … |

A page whose name ends in `-stroke` is an outline layer drawn under the main
one. It is **not** a glyph page; ignore it when enumerating.

Examples from the stock install:

```
_miso light 15x15 (res 360x360).png
_miso light [alt] 10x10 (res 240x240).png
_japanese 24px [kanji-jis2] 63x54 (doubleres).png
_Thai 16px [Sara2] 8x2.png
```

### Resolution hints

Source dimensions default to the image's real pixel size, then:

- `res WxH` **replaces** them (regex `\([^\)]*res (\d+)x(\d+).*\)`, non-square
  allowed);
- `doubleres` **halves** them afterwards.

`sourceFrameWidth = sourceWidth / cols`, and **every width in the ini is in
those units**. See [01](01-engine-internals.md#texture-dimensions-and-the-res-wxh-hint)
for a worked example. Get this wrong and glyphs are cropped to a sliver with no
error.

## Sections

`[common]` applies to every page; a `[<pagename>]` section overrides it for
that page. Both are read by the same function, so any key below may appear in
either.

### Metric keys

| key | default | notes |
|---|---|---|
| `Baseline` | centred in frame | distance from cell top to the baseline, source units |
| `Top` | centred in frame | only used for `m_iHeight = Baseline - Top` |
| `LineSpacing` | source frame height | set it explicitly; it drives line pitch |
| `DefaultWidth` | — | advance for frames with no explicit width |
| `AdvanceExtraPixels` | 0 | added to every advance |
| `DrawExtraPixelsLeft` / `Right` | 0 | widen the drawn quad; clamped, see [01](01-engine-internals.md#fontpagesetextrapixels) |
| `ScaleAllWidthsBy` | 1.0 | multiplies all widths |
| `TextureHints` | — | e.g. `grayscale 16bpp` |
| `CapitalsOnly` | — | used by `_Thai 16px`; not relevant to generation |

### Width keys

Any key that is a bare integer is a **frame index → advance** mapping:

```ini
0=6
1=7
```

Widths are in source units and apply per frame, not per character.

### Character mapping

Three directives, all case-insensitive:

```ini
Line 0= !"#$%&'()*+,-.      ; chars laid out from frame row*cols
map U+1EA1=42               ; one codepoint to one frame
map oq=17                   ; or an alias from FontCharAliases
range unicode #1EA0-1EF9=0  ; contiguous codepoints to consecutive frames
range cp1252=0              ; a named charmap
range iso-8859-2 #80-FF=128 ; a slice of one
```

Named charmaps available (`FontCharmaps.cpp`): `ascii`, `iso-8859-1`,
`cp1252`, `iso-8859-2`, `basic-japanese`, `korean-jamo`, `numbers`.
`range unicode` requires an explicit `#start-end` and is capped at 16384
glyphs per page.

`Line N=` is the compact form and the one this tool emits. The value is taken
**verbatim** including leading spaces, so a leading space maps the space
character — which is why stock pages start `Line 0= !"#$…`.

### Implicit charmaps

If a page section defines no characters at all, a default is applied based on
frame count:

| frames | implicit map |
|---|---|
| 128 | `ascii` |
| 256 | `cp1252` |
| 15 or 16 | `numbers` |
| anything else | nothing — the page has no glyphs |

`frutiger 24px` relies on this: its pages are 16×16 = 256 frames with no `Line`
directives, so it is implicitly CP1252. A reader that only understands `Line`
will think that font is empty.

### Non-breaking space

After parsing, if `' '` is mapped and `U+00A0` is not, `U+00A0` is aliased to
it automatically.

## Encoding

Files are UTF-8. Some stock files carry a BOM (`_Thai 16px.ini` does) — strip
it, hence `utf-8-sig` in `smfont.parse_ini`.

Line endings vary. **Preserve whatever the file already uses.** Python's
universal-newline reading silently converts `\r\n` to `\n`, and writing that
back rewrites every line ending in the file. `fontpatch.patch_import` works on
bytes and detects the existing EOL for exactly this reason — an early version
normalised Simply Love's CRLF file to LF as a side effect of a one-line edit.

## A minimal generated page

What this tool emits for Vietnamese, trimmed:

```ini
# Generated by fontpatch.py - do not hand-edit, it is rewritten on install.
# Glyph source: _miso light.ini
#
# Composited from that font's own letterforms and diacritics.
# Cells are taller than the source page so stacked tone marks have
# headroom above capitals; Baseline and Top are shifted by the same
# amount, so Baseline-Top (the line height) is unchanged.

[common]
Baseline=24
Top=9
LineSpacing=24
DrawExtraPixelsLeft=2
DrawExtraPixelsRight=2

[main]
Line 0  =ẠạẢảẤấẦầẨẩ
Line 1  =ẪẫẬậẮắẰằẲẳ
...

0=9
1=7
...
```

paired with `_fontpatch vietnamese 10x10 (res 240x300).png` — a 10×10 grid,
source cell 24×30, art cell 128×160.
